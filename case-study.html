Task Backlog Prioritization Platform

A full-stack platform that replaced manual spreadsheet-based backlog triage with a transparent, configurable prioritization engine.

JavaScript / TypeScriptReactAWS LambdaDynamoDBInternal authenticationVitest

01 · Summary

From manual triage to an explainable system.

The platform scores every open task from 0 to 100 across five weighted dimensions, allocates a sprint bounded by team capacity, and records an auditable breakdown for every run. It saves an average of 5–10 hours per sprint-planning cycle and increases backlog throughput.

02 · The problem

Planning was slow, inconsistent, and impossible to audit.

A large and continuously growing task backlog was prioritized manually in spreadsheets. Results varied between planners, rankings could not be reproduced, and changes to prioritization criteria required repeated manual work. There was no durable record explaining why an item ranked where it did.

03 · My role

Sole engineer, end to end.

I designed and built the platform: the React interface, JavaScript-based AWS Lambda functions, DynamoDB data model, prioritization engine, automated test suite, security hardening, internal authentication integration, and cloud automation architecture.

04 · The solution

A ranked, capacity-bounded sprint on demand.

The engine evaluates type, keyword signals, request category, age, and workflow stage. It fills a sprint according to team capacity and presents the remainder as ranked overflow. Named presets let the team adjust weights without engineering involvement, while a full change history keeps configuration auditable.

Each run stores a per-task score breakdown so any ranking can be reproduced and explained. Managed scheduling keeps the plan current without a recurring manual process.

06 · Engineering decisions

Decisions shaped by explainability, security, and growth.

Configurable scoring presets

Weights are configuration rather than hard-coded logic. Teams can retune priorities without a deployment, and every change remains traceable.

Full score breakdowns

Persisting each dimension’s contribution turns an opaque ranking into a reproducible answer to “why did this rank here?”

Deterministic, hardened scoring

Scores are clamped to 0–100, ties resolve deterministically, invalid values are handled safely, and configurable matching protects against regular-expression injection and denial-of-service risks.

Serverless backend

AWS Lambda separates application and scoring workflows into independently managed functions. DynamoDB provides durable storage for configuration, task data, scoring results, and audit history.

Resilient automation

Managed scheduling provides retries and an audit trail. Paginated data access and crash-resilient batches maintain correctness as the backlog grows and prevent record loss during partial failures.

Accessibility as a build requirement

An automated lint gate prevents keyboard and screen-reader support from silently regressing.

07 · Outcome

Faster planning with a defensible result.

The platform replaced spreadsheet triage with transparent, reproducible ranking. It saves an average of 5–10 hours each planning cycle, increases backlog throughput, and reduces time spent reviewing low-priority overflow.
